## 2025-02-14 - O(1) Cache Lookups for Single Project Metrics
**Learning:** Extracting an individual project's metrics by rebuilding a complete metrics list containing all projects—even if that full list is built from cached values—forces O(N) looping, allocations, and operations for a simple single-item lookup. When scaling to many projects, this introduces a hidden bottleneck on frequently accessed routes (like `/api/projects/{name}` and MCP tools).
**Action:** When a global object state is cached (e.g., `all_project_metrics`), separate the caching retrieval logic (`_get_cached_metrics`) from the list-rendering logic (`_project_metrics_list`). Use `cache.get(id)` (an O(1) operation) for single entity lookups, instead of generating a full list and iterating/filtering to find the specific item.
