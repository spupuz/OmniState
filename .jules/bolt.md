## 2026-10-05 - Optimize Large Result Set Iteration in SQLite
**Learning:** Explicit dictionary instantiations in SQLite row factory conversions (e.g. `[dict(r) for r in rows]`) during large `fetchmany` loops are extremely expensive in Python due to interpreter overhead and memory churn.
**Action:** For performance-critical loops scanning large tables (like dashboard aggregations), bypass generic iterator wrappers like `q_iter` and stream natively via `self._conn.execute()` and `.fetchmany()`. Access `sqlite3.Row` values directly via keys or indices and only cast to `dict()` when an individual row must be strictly stored for downstream logic, discarding the rest to dramatically reduce allocation overhead. Additionally, use `yield from map(dict, rows)` instead of standard list comprehension yielding to speed up generic `q_iter` operations.
