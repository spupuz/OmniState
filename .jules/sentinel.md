## 2024-09-11 - Arbitrary File Read via symlink traversal in backup script
**Vulnerability:** When creating backups of configuration files, the script used `cat` to copy contents. If the source file was a symlink, `cat` would follow it and read the target file's content into the backup, leading to an Arbitrary File Read vulnerability if the backup directory is readable.
**Learning:** When mitigating symlink traversal vulnerabilities using mktemp, use cat "$src" > "$tmp" to copy standard file contents safely. However, if the source file might be a symlink (e.g., a configuration file backup), using cat is an anti-pattern that introduces an Arbitrary File Read vulnerability by following the symlink to read the target's contents. In such backup scenarios, use cp -a to safely copy the symlink as a symlink.
**Prevention:** Check if the file is a symlink (`[ -L "$file" ]`) and use `cp -a` to copy it as a symlink instead of using `cat` to read its contents.

## 2024-05-18 - Use mktemp -d for atomic, symlink-preserving backups
**Vulnerability:** Arbitrary File Read / Symlink Destruction via `cat`
**Learning:** When mitigating symlink traversal, `mktemp` provides atomic file creation. However, using `cat "$src" > "$tmp"` to write to the temp file is unsafe if `$src` might be a symlink (e.g. a configuration file). `cat` will dereference the symlink and write its contents to the temp file, effectively destroying the symlink structure and potentially exposing target files. Conversely, using `rm -f "$tmp" && cp -a "$src" "$tmp"` re-introduces a Time-Of-Check to Time-Of-Use (TOCTOU) race condition, allowing an attacker to place a malicious symlink in the exact moment after deletion.
**Prevention:** To securely backup a file that might be a symlink while preserving its properties and avoiding TOCTOU, use `mktemp -d` to create a secure, isolated temporary directory. Then, use `cp -a "$src" "$tmpdir/file"` to copy the file into the directory, and move it safely.
